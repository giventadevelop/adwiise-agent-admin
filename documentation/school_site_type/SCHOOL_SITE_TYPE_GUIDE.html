School Site Type

Site type SCHOOL for campuses on the existing multi-tenant platform. India fee collection sits beside Stripe. Updated 7 November 2026.

SCHOOL is a tenant site type for schools and campuses. A school satellite is the same deployment pattern as an existing satellite: its own domain, its own NEXT_PUBLIC_TENANT_ID, and the same Spring API. Content is tenant data. Do not copy another school's prose or photos into the product.

What SCHOOL is

What the site type does

The catalog row is SCHOOL, label School, hint Schools and campuses, module key SCHOOL. It is stored on tenant_organization.site_type.

school_name on a youth-competition participant is a field on that registration. It is not this site type.

Do not reuse the executive committee for teachers. executive_committee_team_members is a church or organization committee (designation, bio, social links). School staff needs qualification, stage, subject, and class-teacher assignment. Mixing them would show teachers on church sites.

How a school site is wired

Request path

School admin uses adwiise-agent-admin at /admin/school.

The admin app calls adwiise-agent-service with a service JWT and X-Tenant-ID.

The service writes Postgres. The public satellite reads the same API when site_type is SCHOOL.

A parent pays an open fee invoice. Razorpay checkout records a school_fee_payment row. The webhook marks the invoice paid. Stripe ticket and membership flows stay on their own tables.

Postgres, not Strapi

System of record

Strapi in this platform is a narrow CMS for news advertisement slots and liturgical readings. School staff, departments, fees, and admissions join tenant id and payments through the same admin REST API as events.

  • Postgres holds tenant isolation, foreign keys, fee amounts, and payment status.
  • Long text such as the principal's message, about, and a club page is a school_page row, so one admin screen owns the school site.
  • Putting teachers or fee invoices in Strapi would split admin, break payment joins, and add a second auth model.
The canonical script is adwiise_agent_Latest_Schema.sql. New school tables use a sequence per table, matching the rest of that file. The shared sequence_generator is dropped at the top of the script, so these tables do not use it.

New school tables

Every school table is tenant-scoped with tenant_id, created_at, updated_at, and the update_updated_at_column trigger. Departments and staff reference each other: the department is created first, staff points at a department, then head_staff_id is added.

Content tables
Table Purpose Important columns
school_staff_member Teachers, administration, and supporting staff staff_category is ADMINISTRATION, TEACHING, or SUPPORTING. stage is KG, LP, UP, HS, HSS, or ALL. Also name, designation, qualification, subject, class teacher, department, contact, photo, bio, and priority.
school_department Subject departments name, slug, summary, body, image, head_staff_id, sort order. Unique (tenant_id, slug).
school_facility Labs, library, bus, music room Name, slug, summary, body, image, sort order. Unique (tenant_id, slug).

school_highlight Homepage merit names Person name, subtitle (class and year), image, academic year. These are not events and not staff.
Fee tables

Fee collection is separate from ticket sales. Stripe ticket columns stay on event_ticket_transaction.

Table Purpose Important columns
school_fee_invoice A fee the parent can pay fee_kind is ADMISSION, TUITION, TRANSPORT, or OTHER. status is DRAFT, OPEN, PAID, or VOID. amount_due is numeric(21,2). Currency defaults to INR.
school_fee_payment One provider attempt against an invoice invoice_id, provider_name, provider order id, provider payment id, amount, currency, status, paid_at.

Invoice fields a payer sees

  • title and academic_year
  • student_name and class_label
  • payer_name, payer_email, and payer_phone
  • due_date

India fee payments

Stripe stays, Razorpay collects school fees

Stripe remains the card path for tickets and memberships. Those amounts stay in USD unless that tenant's Stripe account is India-enabled. School fee invoices are INR and need UPI, netbanking, and Indian cards.

Provider Role Status
RAZORPAY One Checkout for UPI, Visa, Mastercard, Amex, RuPay, netbanking, and wallets Orders plus webhook are implemented
NTT_DATA Same invoice and school_fee_payment rows, different redirect and hash Name is allowed. Checkout returns not enabled until a merchant hash spec is in hand
STRIPE Existing ticket and membership flows Unchanged. Do not send Razorpay payments through StripeFeesTaxService

payment_provider_config

  • check_provider_name includes RAZORPAY and NTT_DATA
  • check_payment_use_case includes FEE_COLLECTION
  • Publishable values and gateway settings go in publishable_key and configuration_json
  • Secrets stay in provider_secret_key_encrypted
Batch jobs stay Stripe-only for fee, tax, and refund sync. There is no Razorpay settlement job in this slice. PaymentProvider in the service and the batch-job copy both include the two new names so a config row can be stored.
Runtime keys for the first Razorpay adapter. The checkout route reads RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET, or the AMPLIFY_ copies. The webhook reads RAZORPAY_WEBHOOK_SECRET. The route is route.ts under /api/webhooks/razorpay and /api/school/fee-checkout.
Checkout result
  1. The admissions page lists open invoices whose fee_kind is ADMISSION.
  2. POST /api/school/fee-checkout accepts only an OPEN invoice with a positive INR amount.
  3. Razorpay returns an order. The app inserts school_fee_payment with provider RAZORPAY and status CREATED.
  4. The webhook verifies x-razorpay-signature, then on payment.captured sets the payment to CAPTURED and the invoice to PAID.
  5. A request with provider NTT_DATA returns HTTP 501 and does not create a second invoice model.

Admin screens and the preset

Where an operator works
  • Onboarding and the organization form offer School.
  • Choosing SCHOOL applies the school preset in siteTypePresets.ts.
  • The preset turns on events, news, gallery, downloads, about, and contact.
  • The preset leaves sports tournaments, league standings, squad sections, and retail packs off.
  • /admin/school edits staff, departments, facilities, activities, pages, highlights, and fee invoices. Staff lists group by category and stage.
  • Lower priority_order or sort_order appears first.
Admissions content. Publish a school_page with slug admissions, then an open school_fee_invoice of kind ADMISSION. A full application form waits until a school asks for that workflow.
