Platform billing Stripe test guide

Use Stripe test mode. Day and week intervals are rejected unless the secret key starts with sk_test_. Production catalog plans stay month or year.

Create a new billing-test organization. Do not use organizations 18, 19, or 20. Do not click Make inactive, Make active, or Cascade Delete on an existing organization.

End-to-end test

This walk-through starts with a platform super admin, adds a charge, picks a plan, then switches to a tenant admin to pay. Use Stripe test mode. The success card is 4242 4242 4242 4242, any future expiry, any CVC.

WhoCan doCannot do
Platform super admin Create a catalog plan. Open /admin/platform-billing/{tenantId}. Turn the charge switch on. Set the catalog, custom fee, review-by date, and grace days. Cancel now. Nothing on this fee is hidden from them. They can also open Pay on /admin/billing.
Tenant admin Open /admin/billing for their website. Click Pay. Update the card. Cancel at period end. Cannot open the plans page or the website charge page. Those send them away. They do not see a switch they can turn on.

Before you start

  1. Sign in as a platform super admin. The database role is SUPER_ADMIN.
  2. Have a second user who is ADMIN on the test website only. You will sign in as that person to pay.
  3. In a second window, forward Stripe test events. The command is in section 1 below. Leave that window open until the payment finishes.
  4. Use a test website. Do not change organizations 18, 19, or 20.

Super admin: add the plan and turn charging on

  1. Open /admin/platform-billing/plans. Click Add plan.
  2. Set Product to Event site. Type a name such as Test day and a code such as test-e2e-day. Set List price to 1.00. Set Billing to Recurring or one-time. Leave Stripe price id blank. Check Published. Click Create plan. A published plan is what the website catalog can show. An unpublished plan stays off that list until you assign it.
  3. Open /admin/platform-billing. Open the test organization, then open the test website. The address is /admin/platform-billing/{tenantId}.
  4. On the Event site card, choose the plan you just created in Catalog plan. Leave Custom fee blank so the catalog price is used. Review-by date can stay empty. It is only a reminder. Set Grace days to 14 for a normal test, or 0 if you want the unpaid lock to happen on the next page open.
  5. Turn the Charge switch on and confirm. The status becomes Payment due. Stripe is not charged by the switch. Click Save event site billing if you still need to store the plan or the grace days.
  6. Sign out.

Tenant admin: pay

  1. Sign in as the tenant admin for that website.
  2. Open /admin/billing. Confirm there is no charge switch you can turn on. The Event site card shows Payment due and a Pay button.
  3. Click Pay monthly. Stripe Checkout opens. Pay with 4242 4242 4242 4242.
  4. You return to /admin/billing. The status becomes Active after the webhook is received. The Charges table shows a Paid row.

Super admin: confirm the payment

  1. Sign in again as the platform super admin.
  2. Open /admin/platform-billing and search the organization. The Status column shows Active. Export ledger shows a PAID row and a Stripe invoice id. The same invoice is in the Stripe test dashboard.
  3. Optional failure check, on a second website or after canceling this one: turn the switch on, click Pay, and use the failing card 4000 0000 0000 0341. The ledger status is FAILED. If grace has ended and nobody has paid, the next open of the billing page sets Locked. Admin tools then send that admin to billing. The public site stays up.
  4. Optional cancel check: the tenant admin can click Cancel at period end. Only the super admin sees Cancel now on /admin/platform-billing/{tenantId}.
A retried Stripe event with the same event id does not insert a second ledger row. A ticket purchase in the same Stripe test account must not appear as a platform charge.
1. Listen for webhooks

Forward Stripe test events to this app with stripe.exe. The admin app in local development is port 3001.

Setup
stripe listen --forward-to http://localhost:3001/api/webhooks/stripe
Windows single-line
stripe listen --forward-to http://localhost:3001/api/webhooks/stripe
The success card is 4242 4242 4242 4242, any future expiry, any CVC. The failure card is 4000 0000 0000 0341.

3. What to confirm
  1. Create the billing-test organization and its home website. Leave organizations 18, 19, and 20 unchanged.
  2. On the website billing page, turn the event-site switch on and choose test-every-day.
  3. Open Pay and complete Checkout with the 4242 card.
  4. In /admin/platform-billing, search the organization. The ledger export shows a PAID row and the Stripe invoice id. The same invoice is in the Stripe test dashboard.
  5. Start a second subscription attempt with the failing card. The ledger status is FAILED. After grace ends with no paid period, the website status becomes LOCKED and admin tools redirect to billing. The public event page stays up.
  6. Cancel at period end as the paying admin. Cancel now is only on the super-admin website page.
  7. On the organization, switch from per website to one organization charge, then back. Covered websites show the organization name and hide Pay. Switching back does not charge a website by itself.
  8. Buy a ticket in the same Stripe test account. That payment must not insert a platform charge. Ticket money stays on the ticket transaction.
A retried Stripe event with the same event id does not insert a second ledger row.
