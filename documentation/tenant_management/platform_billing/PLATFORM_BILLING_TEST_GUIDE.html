Platform billing Stripe test guide

Use Stripe test mode. Day and week intervals are rejected unless the secret key starts with sk_test_. Production catalog plans stay month or year.

Create a new billing-test organization. Do not use organizations 18, 19, or 20. Do not click Make inactive, Make active, or Cascade Delete on an existing organization.

1. Listen for webhooks

Forward Stripe test events to this app with stripe.exe. The admin app in local development is port 3001.

Setup
stripe listen --forward-to http://localhost:3001/api/webhooks/stripe
Windows single-line
stripe listen --forward-to http://localhost:3001/api/webhooks/stripe
The success card is 4242 4242 4242 4242, any future expiry, any CVC. The failure card is 4000 0000 0000 0341.

3. What to confirm
  1. Create the billing-test organization and its home website. Leave organizations 18, 19, and 20 unchanged.
  2. On the website billing page, turn the event-site switch on and choose test-every-day.
  3. Open Pay and complete Checkout with the 4242 card.
  4. In /admin/platform-billing, search the organization. The ledger export shows a PAID row and the Stripe invoice id. The same invoice is in the Stripe test dashboard.
  5. Start a second subscription attempt with the failing card. The ledger status is FAILED. After grace ends with no paid period, the website status becomes LOCKED and admin tools redirect to billing. The public event page stays up.
  6. Cancel at period end as the paying admin. Cancel now is only on the super-admin website page.
  7. On the organization, switch from per website to one organization charge, then back. Covered websites show the organization name and hide Pay. Switching back does not charge a website by itself.
  8. Buy a ticket in the same Stripe test account. That payment must not insert a platform charge. Ticket money stays on the ticket transaction.
A retried Stripe event with the same event id does not insert a second ledger row.
