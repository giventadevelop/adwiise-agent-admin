Platform billing Stripe test guide

Use Stripe test mode. Day and week intervals are rejected unless the secret key starts with sk_test_. Production catalog plans stay month or year.

Create a new billing-test organization. Do not use organizations 18, 19, or 20. Do not click Make inactive, Make active, or Cascade Delete on an existing organization.

End-to-end test

This walk-through starts with a platform super admin, adds a charge, picks a plan, then switches to a tenant admin to pay. Use Stripe test mode. The success card is 4242 4242 4242 4242. Also fill expiry 12/34, security code 123, name Test User, and ZIP 10001. Uncheck Save my information so Checkout does not ask for a phone.

Before you start

  1. Sign in as a platform super admin. The database role is SUPER_ADMIN.
  2. Have a second user who is ADMIN on the test website only. You will sign in as that person to pay.
  3. Windows does not include the Stripe CLI. If Command Prompt says 'stripe' is not recognized, install it with the first command in section 1, then close Command Prompt and open it again. You can still create the plan and turn the charge switch on without that program.
  4. Start the listener in section 1 before you click Pay monthly. Leave that window open until the payment finishes. Stripe sends the payment-succeeded message to http://localhost:3001/api/webhooks/stripe. If the listener is not running, the card can succeed in Checkout while the billing page stays Payment due and the Charges table stays empty.
  5. Use a test website. Do not change organizations 18, 19, or 20.

Super admin: add the plan and turn charging on

  1. Open /admin/platform-billing/plans.
  2. If Test every day (code test-every-day) is already in the list, open it. Leave Stripe price id blank. Check Published. Click Update plan. The Catalog plan dropdown only lists published plans, so this $1.00 Event site plan stays hidden until you publish it. The first payment creates the Stripe price.
  3. If that plan is not there, click Add plan. Set Product to Event site. Type a name such as Test day and a code such as test-e2e-day. Set List price to 1.00. Set Billing to Recurring only. Leave Stripe price id blank. Check Published. Click Create plan.
  4. Open /admin/platform-billing. Open the test organization, then open the test website. The address is /admin/platform-billing/{tenantId}.
  5. On the Event site card, choose that published plan in Catalog plan. Leave Custom fee blank so the catalog price is used. A custom fee replaces the catalog price for that website. Saving a custom fee clears the catalog dropdown to No catalog plan. Choosing a catalog plan again clears the custom fee. The charge interval stays the one already on the website, so a daily fee stays daily. Pay monthly and Pay once save the fee first. If the subscription is already active, Pay changes that subscription to the new amount and does not open Checkout at the old price. Review-by date can stay empty. It is only a reminder. Set Grace days to 14 for a normal test, or 0 if you want the unpaid lock to happen on the next page open.
  6. Turn the Charge switch on and confirm. The status becomes Payment due. Stripe is not charged by the switch. Click Save event site billing if you still need to store the plan or the grace days.
  7. Sign out.

One invoice is one charge. Stripe sends checkout.session.completed, invoice.paid, and invoice.payment_succeeded for the same payment, and a repeated event id is skipped too. A later day of the daily plan is a new invoice and a new row. A ticket purchase in the same Stripe test account must not appear as a platform charge.
1. Install Stripe CLI, then listen for webhooks

The command stripe is a separate program. Windows does not include it. If Command Prompt says 'stripe' is not recognized as an internal or external command, install the Stripe CLI, close Command Prompt, and open a new one. You can create a plan and turn the charge switch on without it. Start the listener before Pay monthly. Leave that window open while you pay with 4242 4242 4242 4242. Without it, Checkout can still take the card, and this app never hears that the payment succeeded. The status stays Payment due and the Charges table stays empty.

The current Stripe CLI also stops if you omit the events flag. The message is must specify events to forward using --events, --all-snapshot, or --all-thin. Add --all-snapshot. That sends the full event this app already reads. Do not use --all-thin for this test. A thin event is only a short notice, and the billing page stays Payment due.
