Tenant platform billing guide

How event-site tenants and gas-station tenants pay to use this platform. Charging is live: a platform super-admin turns the charge switch on, and the paying admin uses Pay on the billing page.

A new tenant uses the product for free until a platform super-admin turns a charge switch on. A reminder date does not start a charge. Payment, when it starts, goes through the Stripe account this app already uses. Zoho Billing is not the payment system. The comparison is in STRIPE_VS_ZOHO_ANALYSIS.md.

1. Two different kinds of money

This platform already takes two kinds of payments. This guide adds a third. Keep them separate.

Kind Who pays What to do
Ticket money A guest buying tickets Leave the existing Checkout and Apple Pay / Google Pay flows alone.
Membership money A person joining as a member Leave membership tables, success pages, and the wallet button alone.
Platform money The organization that runs the event site, or the owner of the gas stations This guide. One Stripe customer per tenant. Event-site fees and gas-station fees are separate products.
Same words, different bills. The tenant admin form already shows plan names such as Basic and Professional, and membership pages already say “subscription.” Those labels are not a live bill for the software.
2. What the tenant is buying
  • Event site. A flat fee for the event website and its admin tools.
  • Gas station. A fee that normally grows with the number of locations on the bill. One subscription for the chain, not one per store.

For each product the tenant can be offered a published catalog plan, or a custom fee typed for that tenant only. The plan can allow a repeating charge, a one-time charge, or both. A long free period is the default: no card on file until a person turns charging on.

A hybrid tenant can be free on one product and paying on the other.

3. The charge switch

This is the main rule.

  1. When a tenant is created, the charge switch for each product is off.
  2. While it is off, the tenant uses that product freely. Stripe is not called. No invoice is created. No card is stored.
  3. Only a platform super-admin can turn the switch on. The tenant cannot. A reminder date cannot.
  4. The admin may set a review-by date (30, 90, 180 days, or any date). That date is a reminder on the admin screen. It does not charge anyone.
  5. When the switch is turned on, the tenant chooses how to pay and gets a grace period (default 14 days) to finish. Access stays open during grace.
  6. If grace ends with no successful payment, paid admin tools for that product stop. The public site and the stored data stay. A pay page explains what to do.
  7. Turning the switch off again stops future charges. It does not delete the tenant. If Stripe is already billing them, the admin confirms whether the current period finishes or the charge stops now.
Status Meaning
Complimentary Switch off. Using the product for free.
Payment due Switch on, still inside grace, no successful payment yet.
Active Switch on and paid.
Past due A renewal failed and Stripe is still retrying.
Locked Switch on, grace over, not paid. Paid tools are blocked.
4. Plans the tenant can choose

A platform super-admin keeps a small catalog. Each plan has a readable name, a product (event site or gas station), whether it is recurring, one-time, or both, the interval, the list price in US dollars, a short feature list, and a published flag. Unpublished plans are hidden from tenants.

The tenant sees only published plans for products they actually have.

Placeholder prices, not a quote. Event site Starter $49 per month, Standard $149 per month, and a Custom plan with no list price. Gas stations use the location rates in the next section, or a custom flat amount. Set the real numbers before the first live charge. A yearly price, if offered, is a separate published price on the same plan.
5. A custom fee for one tenant

When a tenant will not pay the catalog price, a platform super-admin types a custom monthly amount or a custom one-time amount, with cents (for example 199.00), plus a short note. The plan name can still show which feature set they bought. The amount charged is the custom amount.

Stripe then gets a price that exists only for that tenant. Other tenants keep the shared catalog price.

  • If the admin changes a recurring custom amount, the next invoice uses the new amount. The current period is not re-billed unless the admin also chooses “apply now,” which prorates.
  • A one-time payment already collected is not charged again. A new amount applies only if the admin sends a new pay link.
6. Gas stations and location count
  • One subscription for the tenant, not one per store.
  • The tenant or the admin marks which locations are included.
  • The billable count is how many locations are active and included. Do not type the count by hand.
  • Default rates are graduated, so adding a location never makes the total go down.
Locations Each location per month Example
1 to 3 $199.00 2 locations = $398.00
4 to 10 $149.00 for those extra locations 6 locations = (3 × $199.00) + (3 × $149.00) = $1,044.00
11 or more $99.00 for those extra locations Placeholder until a real enterprise price is set

A custom flat fee replaces this math. Quantity is then ignored. Adding or removing an included location after they are subscribed changes the next invoice and prorates the current period.

The older gas-station note in the mosc-temp repo describes the same location idea. This folder is the one to follow, because it also covers event sites, the charge switch, and custom fees.
7. Recurring payment or one-time payment

The admin decides what a plan allows. The tenant chooses only among those options.

Recurring. Stripe charges the card or US bank account on the schedule. The tenant uses the billing portal to change the card or bank account, see invoices, or cancel. Cancel keeps access until the end of the period already paid, unless the admin locks the product sooner.

One-time. Stripe charges once. We store a paid-through date the admin sets (for example 12 months). There is no automatic second charge.

Do not create a Stripe subscription for a one-time plan. A subscription always tries to charge again.
8. How they pay: card and bank

The pay page is Stripe’s hosted Checkout. We do not build a card form for this fee, and we do not store card numbers.

  • Credit or debit card.
  • Apple Pay, Google Pay, or Link, when the device offers them.
  • A US bank account (ACH debit), when the charge is in US dollars and the bank is in the United States.

ACH is cheaper on large bills (about 0.8 percent, capped at $5, on Stripe’s published US pricing). A card is about 2.9 percent plus 30 cents, and an international card costs more. ACH is not instant. Until Stripe reports success, the status stays “payment due,” not “active.”

Tenants outside the United States pay by card or wallet on the same page. Do not offer ACH for a non-US bank. A separate Zoho account is not required for international cards.

After the first successful payment, “Manage billing” opens the Stripe Customer Portal.

Confirm Stripe’s published fees in the Dashboard before the first live tenant is charged. The catalog prices in this guide are our placeholders, not Stripe’s fees.
9. What the platform admin does
  1. Create the tenant the way onboarding already works. Both product switches stay off. Status is Complimentary.
  2. If the price was negotiated, type the custom fee and a short note. Leave the switch off.
  3. Optionally set a review-by date so the list can show “review soon.”
  4. When the business is ready to charge, turn the switch on for the event site, the gas stations, or both. Set the grace days (default 14).
  5. Tell the tenant to open the billing page and pay.
  6. After they pay, confirm status Active and that the Stripe customer id and subscription id (or one-time payment id) are stored.
  7. If a renewal fails, Stripe emails the tenant and retries. The admin list shows Past due. Do not build a second retry system.
  8. To stop charging without deleting the tenant, turn the switch off and confirm whether the current period should finish or stop now.
Only a platform super-admin can change the switch, the custom fee, the catalog, or the grace days. A tenant admin can pay, change their card or bank account, and cancel at period end. They cannot set their own price.
10. What the tenant does
  1. Use the product while the switch is off. No pay page is required.
  2. When the admin turns the switch on, open the billing page from the admin home.
  3. Read the plan, or the custom amount, and choose monthly, yearly, or one-time if more than one option is offered.
  4. For gas stations on location pricing, check which locations are included. The page shows the monthly total before they continue.
  5. Continue to Stripe Checkout and pay by card or, in the US, by bank account.
  6. Return to the billing page. It should say Active.
  7. Later, use “Manage billing” to update the card or bank account, download invoices, or cancel.
11. What must not change
  • Ticket Checkout, the mobile wallet button, ticket success pages, and ticket webhooks.
  • Membership subscribe, membership success, membership QR, and membership renewal jobs.
  • Ticket and membership webhook code must ignore events whose metadata says billingScope=platform_tenant.
  • Clerk sign-in and the satellite-domain setup.
  • Public event pages. A locked tenant loses paid admin tools. The first build does not take the public website down.
12. Where the facts live

Store platform billing on its own records, not on membership subscription rows. Keep the Stripe customer id that already exists on the tenant organization. One customer covers both products.

For each product (event site, gas station), store:

  • Charge switch on or off, and the status.
  • Catalog plan id, if they are on a catalog plan.
  • Custom fee amount. Empty means “use the catalog price.”
  • Billing mode actually chosen: recurring or one-time.
  • Review-by date (reminder only) and grace end date (set when the switch turns on).
  • Stripe subscription id for recurring, or the payment id and paid-through date for one-time.
  • For gas stations: which locations are included. Calculate the count. Do not store a typed count.

Every Checkout session for this fee must include this metadata so ticket and membership code can skip the event:

Checkout metadata 
billingScope=platform_tenant

Also send the tenant id, the product (event site or gas station), and whether the charge is recurring or one-time.
