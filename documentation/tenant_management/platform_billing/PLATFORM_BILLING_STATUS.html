Platform billing status

This page says what software billing does today, in plain English. It does not replace the longer guides. Charging a tenant organization for the website is separate from a guest buying a ticket and separate from a person paying membership dues.

The pay path is built and can be exercised in Stripe test mode. There is no fixed live price list in the application. Dollar amounts in the product guide, such as $49 or $149 a month, are examples until the business publishes real month or year prices.

Screens in the admin app

  • /admin/platform-billing — search organizations and export the charge ledger. Open an organization, then open a tenant id to reach that website’s switch.
  • /admin/platform-billing/{tenantId} — platform super-admin turns the charge switch on. {tenantId} is the website’s tenant id. Check Charge switch under Event site or Gas stations, then save. Saving sets payment due and does not charge the card.
  • /admin/platform-billing/plans — create event-site and gas-station catalog plans.
  • /admin/billing — the paying website admin opens Pay or the Stripe Customer Portal. A regular tenant admin cannot turn the switch on here. A platform super-admin signed into that same tenant also sees the switch.
Three kinds of money

The word “plan” is used in three places. Only one of them creates a software subscription in Stripe.

Name people seeWhat it really isWho pays
Site type A label for the kind of website: events, church, sports, music, personal, hybrid, retail, or school. Stored in the site-type catalog. It does not select a Stripe price. Nobody. It describes the website.
Subscription plan catalog Access words such as Basic, Professional, or Enterprise on tenant screens. Those words are not a live Stripe subscription. Nobody, from this catalog.
Membership plan A person joins and renews. That flow keeps its own Stripe subscription id. Do not store a tenant software fee on a membership row. A person paying dues.
Ticket Checkout A guest buys tickets, including Apple Pay and Google Pay. That payment writes a ticket transaction. A guest at an event.
Platform billing plan The software fee. Products are EVENT_SITE and GAS_STATION only. The organization that runs the website.
One Stripe customer stays on the organization. Event-site fees and gas-station fees are separate products, so one website can be free on one product and paying on the other. Ticket and membership webhooks skip events marked billingScope=platform_tenant.
Site type is not a price

Church, school, sports, music, liquor, clinic, and the other site types or shop packs do not have their own Stripe products. A church website is still billed as an event site when a super-admin turns that product’s charge switch on. A gas-station chain is billed as the gas-station product. Retail packs such as liquor store, restaurant, and clinic are shop types, not extra software plans.

If the website isSoftware product used today
Events, church, sports, music, personal, hybrid, or schoolEvent site, when that product’s switch is on
Gas station chainGas station. One subscription for the chain. The quantity is the number of active included locations, unless a custom flat fee is set.

A Stripe price per site type, and a Stripe price per retail pack, are not built. Adding those would be new work.
How a charge moves
  1. A new website starts COMPLIMENTARY. The charge switch is off. Stripe is not called. A review-by date is only a reminder. It never starts a charge.
  2. Only a platform super-admin can turn the switch on, at /admin/platform-billing/{tenantId}. Check Charge switch under Event site or Gas stations, then save. Turning the switch on sets PAYMENT_DUE and a grace end (today plus the grace days, default 14). The card is not charged by the switch itself.
  3. The paying admin opens /admin/billing and clicks Pay. Stripe Checkout collects a card or a US bank account. This app does not show its own card form. Payment methods and invoices open in the Stripe Customer Portal.
  4. A successful payment sets ACTIVE. A bank payment that is still processing stays payment due. A renewal that fails becomes PAST_DUE from Stripe, then LOCKED when grace has ended with no successful payment.
  5. Locked websites can still open the billing page and Pay. Other paid admin tools for that website redirect to billing. The public site stays up. A complimentary website, and a website covered by the organization charge, are not locked because some other website failed to pay.
  6. Cancel at period end keeps access until the period ends. Cancel now is a super-admin action and returns the row to complimentary.
Money on these screens is shown with two decimal places, for example $10.00.
Catalog price, custom price, and one organization amount

Catalog plan for one website

A super-admin keeps plans at /admin/platform-billing/plans. Each plan belongs to Event site or Gas station. It can be recurring, one-time, or both. A new plan defaults to every month. A published production plan uses month or year. The list price is in US dollars. Gas-station plans can store graduated tiers so the monthly total depends on how many locations are included. The Catalog plan dropdown only lists published plans. Check Published and click Update plan before you can choose one. Leave Stripe price id blank. The first payment creates the Stripe price.

The seeded test plans start unpublished. They are Event site plans at $1.00: test-every-day, test-every-2-days, test-every-15-days, and test-monthly. To use Test every day in a local lab, open that plan, leave Stripe price id blank, check Published, and click Update plan. Day and week intervals are rejected unless the Stripe secret starts with sk_test_.

Custom price for one website

When a website will not pay the catalog price, a super-admin types customFeeUsd for that website, with cents, plus a short note. Checkout creates a Stripe Price for that website only. The shared catalog price is left unchanged. A custom fee also skips gas-station location quantity: the quantity stays 1.

One monthly amount for the whole organization

On the organization page, Billing scope has two choices.

ChoiceWhat is saved
Bill the organization once One monthly dollar amount. One subscription on the home website, noted organization-flat. Every other website is covered, its switch is off, and a website subscription is canceled at period end.
Bill each website separately The organization amount is cleared and the organization subscription is canceled at period end. Each website stays complimentary until a super-admin turns that website’s switch on. Nothing is auto-charged.
The organization amount is monthly only. It is not a yearly organization price, and it is not the sum of each website’s catalog plan. Moving a website into an organization that is billed once covers that website. Moving it to an organization that bills each website separately removes the covered note and does not start a charge.
Do not use organizations 18, 19, or 20 for a billing experiment. Create a new billing-test organization.
What is built

Ready for Stripe test mode means the screen and the webhook path exist. It does not mean a live production charge has been confirmed from this documentation pass. A live charge still needs live Stripe keys, published month or year prices chosen by the business, and a completed test-mode run: success card, failing card, organization scope toggle, and a ticket purchase that must not insert a platform charge.

Install the Stripe CLI, then listen

stripe is a separate program. Windows does not include it. If Command Prompt says 'stripe' is not recognized as an internal or external command, run the install command, close Command Prompt, and open a new one. You can save a plan and turn the charge switch on without it. Start the listener before Pay monthly and leave that window open. Stripe sends the payment-succeeded message to this app. If the listener is closed, the card can succeed in Checkout while the billing page stays Payment due and the Charges table stays empty. The current Stripe CLI also stops with must specify events to forward using --events, --all-snapshot, or --all-thin. Add --all-snapshot so the full event is forwarded. Do not use --all-thin for this test. A thin event is only a short notice, and the billing page stays Payment due. Local admin development uses port 3001. Change the port below if this app is listening somewhere else, then use Copy. The full steps are in the test guide.
